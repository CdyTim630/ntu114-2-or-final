\section{Introduction}
便利商店是台灣大學生與上班族取得即時餐食的高頻場域：門市密度高、購買流程快速，且商品營養標示相對完整。然而，消費者在挑選餐點時，往往需要同時權衡價格、熱量、蛋白質、糖、鈉與飽足感等多重因素。若僅以「最低價」為準則，容易選到高糖、高鈉的商品；若只追求「健康」，又可能使單餐花費過高。另一方面，便利商店也經常推出「飯糰＋飲料」、「麵食＋蛋」等組合優惠，使實際支付金額取決於是否啟用優惠組合，而非單品原價的簡單加總。

本研究將上述選餐問題建模為一個同時考量優惠組合、個人化營養限制與歷史多樣性懲罰的混合整數線性規劃（MILP）。使用者指定情境模式（輕食／正餐／宵夜）、基本生理資訊（性別、年齡、身高、體重）、活動量與健康目標（維持／減脂／增肌）後，模型會自動推薦一組符合預算、達到基本營養需求，且兼具多樣性的單餐組合。此決策問題的核心 trade-off 包括：
\begin{itemize}
\item 成本最小化 vs.\ 蛋白質最大化（高蛋白食物通常較貴）。
\item 嚴格遵守營養區間 vs.\ 可行解之存在性（限制過嚴時，模型可能無法找到可行解）。
\item 短期推薦多樣性 vs.\ 客觀「最佳」商品反覆被選中。
\end{itemize}
為兼顧上述目標，本研究在目標函數中加入軟性懲罰項，並以歷史權重 $h_i$ 控制推薦多樣性。考量 MILP 在大型商品集（數百項商品）下可能面臨較長求解時間，本研究另設計啟發式演算法 \textbf{GRASP-LS}（Greedy Randomized Adaptive Search Procedure + Local Search），使系統能在毫秒至秒級時間內回傳可行且近似最優的解，並以 Gurobi 解作為基準量化 optimality gap。

\section{Problem Description}
考慮一位使用者準備在便利商店購買一餐。給定商品集合、各商品價格與營養標示，以及一組「雙品項／三品項」優惠組合，當使用者輸入情境模式、生理資訊、健康目標與預算上限後，系統需決定：
\begin{enumerate}
\item 哪些商品以原價單品方式被選入；
\item 哪些優惠組合應被啟用，並將其包含的商品一併納入推薦；
\item 當預算與營養條件相互衝突時，哪些軟性限制可在最小代價下適度鬆弛。
\end{enumerate}

模型輸出為一份單餐推薦清單，並列示其總熱量、蛋白質、脂肪、碳水、糖與鈉含量。模型須同時處理硬性限制（熱量區間、商品數量上限、預算、鈉硬上限、餐型結構——正餐恰含一份主餐與至少一個蛋白質來源、每餐至多一杯飲料與一份甜點）與軟性限制（蛋白質下限、脂肪／碳水區間、糖／鈉上限）。此外，為避免短期內反覆推薦相同商品，模型以分層歷史記憶對近期重複出現的商品與類別施加懲罰。

\section{Parameter Preprocessing}\label{sec:pre}
使用者輸入無法直接代入 MILP，因此本研究先依 Mifflin--St Jeor 公式將其轉換為單餐營養參數。令年齡 $A$、身高 $H$、體重 $W$、活動係數 $AF \in \{1.2,1.55,1.725\}$、蛋白質係數 $PF \in \{1.1,1.6,1.8\}$，
\[
\text{BMR} = \begin{cases}10W+6.25H-5A+5, & \text{男}\\10W+6.25H-5A-161, & \text{女}\end{cases},\quad
\text{TDEE} = \text{BMR}\cdot AF,
\]
\[
\text{Target}_{\text{Cal}} = \text{TDEE} + \delta_{\text{goal}}, \quad
\delta = \{0, -500, +300\} \text{ for \{維持,減脂,增肌\}},
\]
\[
\text{Target}_{\text{Pro}} = W \cdot PF, \quad
\text{Target}_{\text{Fat}}^{\min,\max} = \frac{\text{Target}_{\text{Cal}}\cdot FF_{\min,\max}}{9},\quad
\text{Target}_{\text{Carb}}^{\min,\max} = \frac{\text{Target}_{\text{Cal}}\cdot CF_{\min,\max}}{4}.
\]
再以情境比例 $\rho_m$ 將每日需求縮放為單餐：$\text{Cal}^{\min,\max}_m = \text{Target}_{\text{Cal}}\cdot \rho^{\min,\max}_m$，依此類推。本研究使用 $\rho^{\min,\max}$ 分別為輕食 $(0.15,0.25)$、正餐 $(0.30,0.45)$、宵夜型 $(0.05,0.15)$。

\section{Mathematical Model}\label{sec:model}
\paragraph{Sets.}$I$ 為商品集合，$K$ 為優惠組合集合，$S_k\subseteq I$ 為組合 $k$ 包含之商品。每項商品依全家官方分類指派一個「餐位角色」$\mathrm{role}(i)\in\{\text{主餐},\text{飲料},\text{甜點},\text{配菜}\}$；令 $I^{\mathrm{main}}, I^{\mathrm{drink}}, I^{\mathrm{dess}}\subseteq I$ 分別為主餐、飲料、甜點集合。$I^{P}\subseteq I$ 為「真實蛋白質來源」，定義為每份蛋白質 $\ge 7$ g 且非甜點之商品（避免高糖甜點被模型誤判為蛋白質來源）。

\paragraph{Parameters.}$c_i$ 單品原價；$cal_i,pro_i,fat_i,carb_i,sug_i,sod_i$ 為商品 $i$ 之營養含量；$c_k^{\text{promo}}$ 為優惠價；$B$ 為預算；$\text{Cal}^{\min,\max}_m, P^{\min}_m,$ \dots 為單餐限制（見 \S\ref{sec:pre}）；$N^{\max}_m$ 為商品數上限；$h_i$ 為歷史重複懲罰權重；$\alpha,\beta,\gamma$ 與 $\lambda_*$ 為目標函數權重。

\paragraph{Decision Variables.}\leavevmode
\[
a_i \in \{0,1\}\ \text{單品選取}, \quad
y_k \in \{0,1\}\ \text{組合啟用}, \quad
x_i = a_i + \sum_{k:\,i\in S_k} y_k \quad\text{(輔助)}.
\]
鬆弛變數：$s_P, s^-_{F}, s^+_{F}, s^-_{C}, s^+_{C}, s_{\text{Sug}}, s_{\text{Sod}} \ge 0$。

\paragraph{Tiered Historical Penalty.}為兼顧「短期不重複」與「久遠商品可再次出現」，本研究將近期推薦過的去重商品，依其「新近排名」$r$ 放入一個仿作業系統多層回饋佇列（MLFQ）的分層結構。排名落入不同區間對應不同階層 $t(r)$，懲罰權重 $w(r)=\omega_{t(r)}$ 隨階層遞減：本研究取邊界 $r\le\{3,8,16,30\}$、權重 $\boldsymbol{\omega}=(5,\,2.5,\,1,\,0.3)$。最近被推薦的商品位於最上層（懲罰最重），若接下來數餐未再被選中，懲罰即逐層淡出；若再次被推薦，則回到最上層（promotion）。保留至 $r\le 30$，更久者丟棄，等效於「極長但有限」的記憶窗。則
\[ h_i = \sum_{r} w(r)\,\mathbf{1}(i\text{ 出現於第 }r\text{ 近的紀錄}). \]
此外定義「類別多樣性懲罰」$g_i = \sum_{r} w(r)\,\mathbf{1}\!\big(\mathrm{role}(\text{紀錄}_r)=\mathrm{role}(i)\big)$，使剛被推薦過的類別整體受到抑制，避免模型僅透過「更換同類商品變體（如不同品牌豆漿）」製造表面上的多樣性。

\paragraph{Objective.}\leavevmode
\begin{align}
\min\;& \alpha\!\left(\sum_{i\in I} c_i a_i + \sum_{k\in K} c_k^{\text{promo}} y_k\right) - \beta\sum_{i\in I} pro_i x_i + \gamma\sum_{i\in I} h_i x_i + \gamma_{\text{cat}}\sum_{i\in I} g_i x_i \notag\\
& + \lambda_P s_P + \lambda^-_{F} s^-_{F} + \lambda^+_{F} s^+_{F} + \lambda^-_{C} s^-_{C} + \lambda^+_{C} s^+_{C} + \lambda_{\text{Sug}} s_{\text{Sug}} + \lambda_{\text{Sod}} s_{\text{Sod}}. \label{eq:obj}
\end{align}
\paragraph{Constraints.}\leavevmode
\begin{align}
&a_i + \sum_{k:i\in S_k} y_k \le 1, \quad \forall i \in I, \tag{C1: 互斥}\\
&\sum_{i\in I} c_i a_i + \sum_{k\in K} c_k^{\text{promo}} y_k \le B, \tag{C2: 預算}\\
&\text{Cal}^{\min}_m \le \sum_{i\in I} cal_i x_i \le \text{Cal}^{\max}_m, \tag{C3: 熱量區間（硬）}\\
&\sum_{i\in I} pro_i x_i + s_P \ge P^{\min}_m, \tag{C4: 蛋白質（軟）}\\
&\sum_{i\in I} fat_i x_i + s^-_{F} \ge \text{Fat}^{\min}_m,\quad \sum_{i\in I} fat_i x_i - s^+_{F} \le \text{Fat}^{\max}_m, \tag{C5: 脂肪（軟）}\\
&\sum_{i\in I} carb_i x_i + s^-_{C} \ge \text{Carb}^{\min}_m,\quad \sum_{i\in I} carb_i x_i - s^+_{C} \le \text{Carb}^{\max}_m, \tag{C6: 碳水（軟）}\\
&\sum_{i\in I} sug_i x_i - s_{\text{Sug}} \le \text{Sugar}^{\max}_m, \quad \sum_{i\in I} sod_i x_i - s_{\text{Sod}} \le \text{Sodium}^{\max}_m, \tag{C7--8: 糖/鈉（軟）}\\
&\sum_{i\in I} sod_i x_i \le \kappa\cdot \text{Sodium}^{\max}_m, \quad (\kappa = 1.5) \tag{C8b: 鈉硬上限}\\
&1 \le \sum_{i\in I} x_i \le N^{\max}_m, \tag{C9: 數量}\\
&\sum_{i\in I^{\mathrm{drink}}} x_i \le 1, \quad \sum_{i\in I^{\mathrm{dess}}} x_i \le 1, \tag{C10: 餐型結構}\\
&\sum_{i\in I^{\mathrm{main}}} x_i = 1, \quad \sum_{i\in I^{P}} x_i \ge 1, \quad \text{當 } m = \text{正餐模式}. \tag{C11: 主餐+蛋白}
\end{align}
其中，(C8b) 為鈉含量的硬性上限：雖然軟限制 (C8) 允許鈉含量略高於目標值，但任何一餐都不得超過 $1.5\times$ 上限，以避免推薦過鹹的組合；(C10) 限制每餐至多一杯飲料與一份甜點；(C11) 要求正餐恰含一份主餐，並至少包含一個真實蛋白質來源，以排除「以三件零食或兩瓶飲料湊成一餐」或「甜點當主菜」等不合理組合。

\paragraph{權重的意義：各目標的相對重要性.} 目標函數中的權重用來控制各項目標的\textbf{相對重要性}：$\alpha$ 對應成本、$\beta$ 對應蛋白質、$\gamma$（與 $\gamma_{\text{cat}}$）對應重複性，各 $\lambda_*$ 則對應各項軟限制被違反的程度。預設 $(\alpha,\beta)=(1,0.5)$ 設定成本與蛋白質之間的權衡幅度，$\lambda_P=6$、$\lambda_{\text{Sug}}=4$、$\lambda_{\text{Sod}}=0.15$ 則決定蛋白質不足、糖與鈉超標各自的懲罰強度。如此可將「健康 vs.\ 成本」的取捨參數化，使用者可透過 App slider 直接調整偏好（見 \S\ref{sec:exp} 之敏感度分析）。

\section{Proposed Algorithm: GRASP-LS}\label{sec:alg}
為降低大規模情境下單純依賴商業 solver 的求解負擔，本研究設計啟發式演算法 \textbf{GRASP-LS}。此方法結合「貪婪隨機構造（GRC）」與「鄰域局部搜尋（LS）」，並透過多重啟動（multi-start）強化全域探索能力。整體流程見圖 \ref{fig:flow} 與演算法 \ref{alg:grasp}。

\paragraph{核心想法.}
\begin{enumerate}
\item \textbf{綜合優先分數} $\sigma(p)$（式 \ref{eq:score}）同時量化每項商品的蛋白質貢獻、價格負擔、營養適配度、類別獎勵與歷史懲罰，使後續貪婪建構更具方向性。
\item \textbf{RCL (Restricted Candidate List)} 機制以參數 $\alpha_{\text{rcl}}\in[0.1,0.4]$ 控制隨機性：$\alpha_{\text{rcl}}\to 0$ 偏向純貪婪，$\alpha_{\text{rcl}}\to 1$ 偏向純隨機；每次 restart 皆隨機抽取候選項，以產生不同的起始解。
\item \textbf{組合作為「超商品」.} 第一步以正比於組合分數的機率嘗試納入一個優惠組合，使啟發式能主動探索「優惠組合－單品選取互斥」的決策邊界。
\item \textbf{結構感知建構.} 建構階段先放入恰好一份主餐，並於加入後續候選時即時遵守「至多一杯飲料、至多一份甜點」之餐型限制（C10--C11），使初始解在結構上即具可行性，降低事後仰賴局部搜尋修補的需求。
\item \textbf{局部搜尋} 使用 1-1 swap、1-0 drop、0-1 add 與 combo-swap 等多種移動，採用「首改善（first-improvement）」策略加速搜尋並降低停滯風險。
\item \textbf{多重啟動} 對 $K_{\text{restart}}=25$ 個不同種子分別執行 GRC+LS，蒐集所有 hard-feasible 解形成解池，回傳目標函數值最小者（或依下述 $\epsilon$-最佳取樣回傳一個多樣化解）。
\end{enumerate}
\begin{equation}\label{eq:score}
\sigma(p) = \beta \cdot pro_p - 0.06\alpha\cdot c_p - \gamma h_p - 0.6\tfrac{cal_p}{\text{Cal}^{\max}_m} - \lambda_{\text{Sod}}\tfrac{sod_p}{\text{Sodium}^{\max}_m} - \lambda_{\text{Sug}}\tfrac{sug_p}{\text{Sugar}^{\max}_m} + B_{\text{cat}}(p).
\end{equation}
其中 $B_{\text{cat}}(p) = 1.2 \cdot \mathbf{1}(p\in I^S) + 1.5\cdot \mathbf{1}(p\in I^P)$。

\begin{algorithm}[h]
\caption{GRASP-LS for the Convenience Store Meal Recommendation Problem}
\label{alg:grasp}
\begin{algorithmic}[1]
\Require Instance $\mathcal{I}=(I,K,S)$；單餐限制 $\mathcal{M}$；權重 $w$；預算 $B$；重啟次數 $K_{\text{restart}}$
\State $s^* \gets \emptyset$；$z^* \gets +\infty$
\For{$r = 1$ \textbf{to} $K_{\text{restart}}$}
  \State $\alpha_{\text{rcl}} \sim \mathcal{U}(0.10, 0.40)$
  \State $s \gets \textsc{GreedyRandomConstruct}(\mathcal{I},\mathcal{M},w,B,\alpha_{\text{rcl}})$
  \Comment{含「先試組合再加單品」分支}
  \State $s \gets \textsc{LocalSearch}(s,\mathcal{I},\mathcal{M},w,B)$
  \Comment{1-1 swap / 1-0 drop / 0-1 add / combo-swap，首改善}
  \State $z \gets \textsc{Evaluate}(s)$
  \If{$s$ 是 hard-feasible 且 $z < z^*$} $\;s^* \gets s$；$z^* \gets z$ \EndIf
\EndFor
\State \Return $(s^*, z^*)$
\end{algorithmic}
\end{algorithm}

\paragraph{時間複雜度.} GRC 每一步檢視 $O(|I|)$ 候選並計算貢獻，最多取 $N^{\max}_m$ 項，故 $O(N^{\max}_m\cdot |I|)$。LS 每輪 1-1 swap 約為 $O(N^{\max}_m\cdot |I|)$；最壞情況下每輪都會改善並進入下一輪。實務上 LS 經過 $T\le 10$ 輪即收斂，總時間為 $O(K_{\text{restart}}\cdot T\cdot N^{\max}_m\cdot |I|)$。

\begin{algorithm}[h]
\caption{Greedy Randomized Construction (GRC) sub-procedure}
\label{alg:grc}
\begin{algorithmic}[1]
\Require Instance、單餐限制、RCL 參數 $\alpha_{\text{rcl}}$
\State $s \gets \emptyset$
\If{$\text{Rand}()<0.6$}
    \State 計算每個 combo $k$ 的 $\sigma_k$；取分數最高的 $\alpha_{\text{rcl}}$-RCL，隨機抽 $k^*$ 加入 $s$ \Comment{若 $|S_{k^*}|\le N^{\max}_m$}
\EndIf
\While{$|s|<N^{\max}_m$}
    \State 篩出未覆蓋、加入後不破預算且不超過 $\text{Cal}^{\max}_m$ 的候選 $C$
    \If{$C=\emptyset$} \textbf{break} \EndIf
    \If{$\sum cal_i$ 已 $\ge \text{Cal}^{\min}_m$ 且 $|s|\ge 2$}
        \State 嘗試 top-3 候選；只有當目標函數改善時才加入，否則 \textbf{break}
    \Else
        \State 依 $\sigma$ 分數取 $\alpha_{\text{rcl}}$-RCL，隨機抽一項加入 $s$
    \EndIf
\EndWhile
\State \Return $s$
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[h]
\caption{Local Search (1-1 swap / 1-0 drop / 0-1 add / combo-swap)}
\label{alg:ls}
\begin{algorithmic}[1]
\Require 解 $s$、最大輪數 $T_{\max}$
\For{$t = 1$ \textbf{to} $T_{\max}$}
  \State $\text{improved} \gets \texttt{false}$
  \ForAll{$p \in s$, $p'\notin s$}
    \If{以 $p'$ 取代 $p$ 後可行且目標下降}
      \State $s \gets s\setminus\{p\}\cup\{p'\}$；$\text{improved}\gets\texttt{true}$；\textbf{break to outer}
    \EndIf
  \EndFor
  \If{\textbf{not} improved} 嘗試 1-0 drop；0-1 add；combo-swap \EndIf
  \If{該輪無任何改善} \textbf{break} \EndIf
\EndFor
\State \Return $s$
\end{algorithmic}
\end{algorithm}

\paragraph{多樣化部署：$\epsilon$-最佳取樣與後備求解.}\label{par:eps}
若系統每次都回傳唯一最佳解，連續查詢容易得到幾乎相同的餐點（MILP 為確定性，僅靠歷史懲罰輪替）。本研究因此將「多樣性」形式化為對 $\epsilon$-最佳解集合 $\mathcal{S}_\epsilon=\{s : z(s)\le z^*+\epsilon\}$ 之均勻取樣：每次查詢皆自解池中，隨機抽取一個目標值落在最佳值 $\epsilon$ 元以內的解作為推薦結果。$\epsilon$ 直接控制「多樣性 vs.\ 最佳性」之 trade-off（量化見 \S\ref{sec:exp} 之「多樣性的代價」）。部署時預設以 GRASP-LS（$\epsilon=8$）提供多樣化推薦；若於極緊預算下 GRASP 偶未找到可行解，則退回 MILP 精確求解作為後備，確保只要存在可行解，系統即可回傳推薦結果。

\section{Data Collection and Generation}\label{sec:data}
\paragraph{Real-world data scraping（兩階段）.}

\textit{階段一：營養標示.} 本研究透過全家便利商店「食在購安心」食品履歷查詢 API（\url{foodsafety.family.com.tw/Web_FFD_2022/ws/QueryFsProductListByFilter} 與 \texttt{QueryFsProductByItem}）爬取 \textbf{581 項真實商品}的官方營養標示，覆蓋 22 個原始分類。所有商品的熱量、蛋白質、脂肪、碳水、糖與鈉資料皆來自官方食品履歷的逐包標示，並以「本包裝含 $n$ 份」自動換算為每包總量。scraper 程式碼見 \texttt{src/scrape\_familymart.py}。

\textit{階段二：價格.} 食品履歷 API 不提供價格。本研究先解析「全家鮮食組合餐促銷頁」（\url{nevent.family.com.tw/freshfood/}）之 \textbf{49/59/69/79/99/109 元} 六個分級，以 n-gram fuzzy 字串相似度對應，命中 \textbf{124 項鮮食}（飯糰、便當、三明治、義大利麵、麵包）之真實店內價。其餘非鮮食品項（乳製品、飲料、零食、冷凍食品等）全家並無公開的「單品店內價」API——「全家行動購」電商目錄雖可爬取（\texttt{fts-api.91app.com}），但其中 78\% 為整箱／多入裝（價格中位數 NT\$149），屬於「整箱價」而非「單品店價」，若直接採用將嚴重扭曲單餐定價（如一碗牛肉麵被標為 NT\$249）。本研究因此對其餘 \textbf{457 項} 採「市售行情校正價」：依分類建立合理的單份店價基準（乳製品約 28、單瓶豆漿約 28、關東煮每串約 20、舒肥雞胸約 59 等），並對標有容量之飲料按毫升微調。最終價格組成為 124 項鮮食實價＋457 項市售校正價（程式碼 \texttt{src/scrape\_freshfood\_prices.py}、\texttt{src/curate\_prices.py}）。因此，本研究明確標註資料來源：鮮食採真實分級價，其餘商品則採依市場行情校正之合理估計價。

\textit{階段三：份量正規化、家庭份過濾與角色標記.} 許多 SKU 為多份包裝（1857 ml 豆漿＝4 份、24 入禮盒等），其營養與價格為「整包」數值而非一餐所含；本研究將所有數值除以份數正規化為「每份」，並對每份價格設下限 NT\$18，避免因整包均價被低估而產生「一份僅 1 元」的假性低價商品，進而不合理地主導推薦結果。家庭份（$\ge 3$ 份，如 1857 ml 大瓶、936 ml 牛乳）並非合理的單餐購買，因此自商品池中移除，581 項過濾後為 \textbf{488 項}。此外，原始 CSV 以關鍵字推得的 \texttt{is\_main}/\texttt{is\_protein} 旗標雜訊偏高（蛋糕、餅乾曾被標為蛋白質來源），本研究改以官方分類重新指派餐位角色（主餐／飲料／甜點／配菜），並將糖 $\ge 10$ g 之甜麵包（菠蘿、拔絲等）改判為甜點，使「真實蛋白質來源」與「主餐」的定義更貼近實際消費情境（程式碼 \texttt{src/data\_loader.py}）。

\textit{組合優惠.} 共 55 組由 main + drink、main + side、main + side + drink 三類規則合成的優惠組合，折扣率設為 17\%--20\%；此部分屬 mock 設定，本研究已於報告中明確標示。

\paragraph{Real-world user profiles.}為展示模型在不同使用者條件下的推薦差異，本研究設計 6 個典型 profile（性別 × 健康目標 × 活動量），各搭配 3 種情境模式，共 18 個 real-world 例題（見表 \ref{tab:real}）。

\paragraph{Random instances.}為驗證可擴展性，本研究依下列因子建立隨機例題：
商品數 $|I|\in\{30,50,80,120,200,300\}$；組合數 $|K|\in\{8,15,25,35,60,90\}$；各規模 5 個隨機種子，共 30 個隨機例題。商品屬性分布如下：
$cal\sim \mathcal{U}(180,650)$（主食）或 $\mathcal{U}(15,320)$（非主食），$pro\sim \mathcal{U}(5,30)$（含蛋白質）或 $\mathcal{U}(0,10)$，$sod\sim \mathcal{U}(0,1400)$；
組合大小 $\in\{2,3\}$，折扣率 $\sim \mathcal{U}(0.80,0.92)$ 之原價。

\paragraph{壓力測試情境（factorial scenario design）.}上述隨機例題主要改變「規模」此一因子。為進一步檢驗 GRASP-LS 在極端條件下的穩健性，本研究另設計一組 $2\times2$ 因子情境：因子一為\textbf{預算水準}（緊 $B=90$／寬 $B=220$），因子二為\textbf{蛋白質目標}（高：增肌目標／寬鬆：維持目標）；於 3 種規模（80／120／200 品項）$\times$ 4 個種子下交叉，共 $4\times3\times4=48$ 個受測例題，各情境同時以 MILP 與 GRASP-LS 求解（程式碼 \texttt{src/run\_extra\_experiments.py}）。結果見 \S\ref{sec:stress}。

\section{Performance Evaluation}\label{sec:exp}
本節以三種解法相互比較：
（i）\textbf{Gurobi MILP}（精確解，作為上下界基準）；
（ii）\textbf{GRASP-LS}（本研究提出之啟發式）；
（iii）\textbf{Greedy baseline}（最簡單之「蛋白質／價格比」貪婪法，作為「very simple heuristic」基準）。
權重設定為 $\alpha=1, \beta=0.5, \gamma=2, \gamma_{\text{cat}}=8, \lambda_P=6, \lambda^\pm_F = 2/3, \lambda^\pm_C = 1/1.5, \lambda_{\text{Sug}}=4, \lambda_{\text{Sod}}=0.15$。基準表（MILP/GRASP/Greedy 比較）皆以空歷史求解，故 $\gamma,\gamma_{\text{cat}}$ 不影響最佳值；多樣性效果另於 \S\ref{sec:exp} 之敏感度與「多樣性的代價」中另行評估。

\subsection{The Price of Diversity}\label{sec:div}
若每次都回傳唯一最佳解，連續查詢容易得到幾乎相同的餐（\S\ref{par:eps}）。本研究以 Gurobi 解池（solution pool, \texttt{PoolSearchMode=2}）窮舉 $\epsilon$-最佳解集合 $\mathcal{S}_\epsilon=\{s:z(s)\le z^*+\epsilon\}$，以量化「犧牲多少最佳性可換得多少多樣性」。以一位男·維持·正餐使用者（最便宜之達標餐 NT\$93）為例，圖 \ref{fig:div} 顯示：$\epsilon=0$ 僅 1 種最佳餐；放寬至 $\epsilon=8$（NT\$8）即有 \textbf{12 種} 結構完整且不同的餐點可選，平均僅多付 NT\$6.7；$\epsilon=16$ 有 \textbf{48 種}、$\epsilon=32$ 更達 \textbf{641 種}，平均成本溢價分別為 NT\$12.8、NT\$20.9。這條曲線即「多樣性的代價」：\textbf{在最佳解附近，取得多樣性的代價相當低}——只需容忍個位數的成本，便可獲得十餘種同樣達標的餐。部署時本研究即以 $\epsilon=8$ 對此集合取樣（以 GRASP-LS 近似 + 分層記憶長期去重），兼顧最佳性與「每次不同」的使用體驗。

\caption{多樣性的代價：隨 $\epsilon$-最佳取樣窗放寬，可選的不同達標餐數由 1 暴增至 641（藍柱），而平均成本溢價（紅線）僅緩升至約 NT\$21。在最佳解附近多樣性極廉。}

\subsection{Executable Recommendations}
以 U1 男·減脂·正餐情境（70 kg，TDEE 2118 kcal，預算 NT\$120，單餐熱量區間 635--953 kcal、蛋白質下限 44.8 g、鈉上限 960 mg）為例。MILP 解為一份結構完整的餐：\textbf{小菠蘿麵包（主餐 NT\$24）＋蜜汁豬肉乾（配菜 NT\$32）＋無加糖濃豆漿（飲料 NT\$28）＋綜合水果軟糖（甜點 NT\$25）}，總價 NT\$110，攝取 693 kcal、45.6 g 蛋白質、667 mg 鈉——恰含一份主餐、至少一個蛋白質來源，並各含一份飲料與甜點，熱量、蛋白質、鈉皆達標。相較之下，以「蛋白質／價格比」貪取的 Greedy 取雞腿排+豬耳絲+豆漿（NT\$118、91 g 蛋白質）卻\textbf{缺主餐}且鈉達 2168 mg（超過 $1.5\times$ 硬上限），因此不可作為合理推薦。本模型的價值並不在於單純追求「最便宜」（一份結構餐約與一個便當同價），而在於\textbf{固定預算下穩定產出「結構合理、營養達標、且每次不同」的一餐}——這是單純比價或貪婪法無法同時兼顧的。

\subsection{Discussion and Limitations}
\paragraph{為何 Greedy 在新模型下 0\% 可行？} Greedy 依「蛋白質／價格比」此單一指標排序並逐項加入商品，必然偏好便宜、高蛋白密度的小型品（雞胸、雞腿、豆漿），結果同時違反多條硬性限制：缺主餐（C11）、品項全為小菜，且高蛋白加工品累積使鈉量突破 $1.5\times$ 硬上限（C8b）。這說明真實的餐食決策是「多重結構限制下的組合最佳化」，任何單一比值排序皆難以勝任——正是本研究 MILP／GRASP-LS 的價值所在。

\paragraph{為何 GRASP-LS 在「正餐」例題 gap 偶爾較大？} 加入「恰一份主餐 + 餐型結構」(C10--C11) 後，正餐之可行組合較窄；當建構階段隨機選定的主餐不屬於最優解，且 LS 的 1-1 swap 鄰域無法一步到達該解時，便會卡在次優（最差約 40\%）。可透過提高 $K_{\text{restart}}$、加入「換主餐」與 2-2 swap 鄰域，或如部署版退回 MILP 後備來改善。

\paragraph{餐型結構大幅提升推薦真實性.} 早期版本在缺少 C10--C11 與角色標記時，可能推出「甜點當主菜」「三件零食湊一餐」「整瓶 1857 ml 豆漿」等雖營養達標但不符合實際用餐情境的組合。本研究以官方分類重定餐位角色、過濾家庭份、並加入「恰一主餐／至多一飲料一甜點」之結構硬限制後，推薦皆呈「一份主餐 + 配菜／飲料 + 至多一份甜點」的真實樣態，明顯提升可採用性。

\paragraph{資料品質與價格估計.} 488 項商品（581 項過濾家庭份後）之營養來自官方食品履歷，具高度可信度；價格則 124 項鮮食為促銷頁真實分級價，其餘 457 項因全家無公開單品價 API、且電商目錄為整箱價（78\% 為多入裝），改採依分類之市售行情校正值——這是本研究主要的資料限制。不過，敏感度測試顯示，將全部價格上下擾動 10\% 後 U1 正餐之最優解結構（主餐＋配菜＋飲料＋甜點）不變，模型對小幅價格誤差具穩健性。

\paragraph{權重選擇.} 本研究預設 $(\alpha, \beta, \gamma)=(1, 0.5, 2)$，並透過敏感度分析說明各權重對解的影響。在實務部署上，這些權重可透過 App slider 介面開放使用者調整，讓使用者自行選擇「重視成本」或「重視蛋白質」；亦可結合個人歷史回饋自動學習。

\section{Conclusions}
本研究將便利商店餐食推薦問題形式化為一個同時包含優惠組合、個人化營養限制、\textbf{餐型結構限制}與\textbf{分層多樣性懲罰}的混合整數線性規劃，並以實際蒐集的 488 項全家商品資料（鮮食為真實分級價、其餘為市售行情校正價）為實證基礎。為兼顧求解品質與實務可用性，本研究自行設計 GRASP-LS 啟發式（含結構感知建構與 $\epsilon$-最佳多樣化取樣），並以 18 個真實例題與 30 個隨機例題進行驗證。主要發現：（1）MILP 於毫秒到秒級求得全域最佳解；（2）GRASP-LS 100\% hard-feasible，平均 optimality gap 為 7.1\%（真實）／4.9\%（隨機）；（3）加入餐型結構與鈉硬上限後，最簡單之 Greedy 法 \textbf{0\% 可行}，凸顯在多重結構限制下進行組合最佳化的必要性；（4）敏感度分析顯示 $\beta$ 以「階梯式」控制成本-蛋白質權衡，分層歷史懲罰可在幾乎不漲價下消除重複；（5）以 Gurobi 解池量化「\textbf{多樣性的代價}」：在最佳解附近，容忍 NT\$8 即有 12 種達標餐可選、NT\$32 達 641 種，顯示在最佳解附近取得多樣性的成本相當低；（6）實作 Flask 互動式 web 應用，含分層「口味記憶」與權重 slider，展示模型具備實際部署潛力。

未來研究可朝以下方向延伸：（a）將模型推廣至「多日連續推薦」與動態庫存／到貨資訊；（b）整合店面實際 OCR 商品標示，自動更新資料表；（c）引入使用者點擊／拒絕回饋的線上學習機制，使 $h_i$ 不僅反映過去推薦紀錄，也能學習使用者偏好；（d）與外送 App 結合，將推薦範圍擴展至多通路（如 7-11、Hi-Life）以及不同時段限定品。
